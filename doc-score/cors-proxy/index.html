Set up the public-page fetch proxy

Use this restricted Cloudflare Worker when a documentation site blocks direct browser requests with a CORS error. This setup is intended for public documentation pages, including the public Salesforce Help article in your example.

Why this is needed

Your screenshot shows a browser CORS error while trying to fetch a page on help.salesforce.com. The browser blocks JavaScript from reading a response when the remote site does not grant the required cross-origin permission. DocScore Lab runs on GitHub Pages, so it cannot change Salesforce's response headers.

The optional Worker makes the request from a server-side environment and returns the page to DocScore Lab with an allowed origin. It does not bypass authentication or any Salesforce access control.

Use this only for public pages. The sample configuration allows help.salesforce.com only. Do not forward Salesforce cookies, SSO credentials, bearer tokens, or internal content.

1. Create a Cloudflare Worker

  1. Sign in to your Cloudflare dashboard. Create a Cloudflare account if you do not already have one.
  2. Open Workers & Pages.
  3. Select Create application, then create a Worker and deploy the starter application.
  4. Open the Worker editor.
  5. In this GitHub repository, open the Worker source file. Copy the complete contents and replace the starter code in the Cloudflare editor.
  6. Save and deploy the Worker.

Cloudflare's current dashboard flow is documented in its Workers dashboard quick start.

2. Configure the hostname allowlist

In Cloudflare, open your Worker and select Settings. Under Variables and Secrets, add these two text variables:

Variable nameValuePurpose
SITE_ORIGINhttps://tanmayi1996.github.ioAllows the DocScore website to read the proxy response.
ALLOWED_HOSTShelp.salesforce.comRestricts outbound fetch requests to this exact hostname.
  1. For each variable, select the text type. These values are configuration, not secrets.
  2. Save the variables and deploy the updated Worker.
  3. Do not use a wildcard hostname. Add only a specific public documentation hostname you trust if you need another site.

See Cloudflare's environment variables guide for the current dashboard steps.

3. Connect the Worker to DocScore Lab

  1. After deployment, copy the Worker URL shown by Cloudflare. It typically ends in .workers.dev.
  2. Open DocScore Lab.
  3. Select Fetch URL.
  4. In Public documentation page URL, paste the Salesforce Help article URL.
  5. In Optional fetch proxy URL, paste the Cloudflare Worker URL.
  6. Select Fetch page. When the page loads, select Analyze documentation.
Example article domain: https://help.salesforce.com/.... Keep the article URL in the first field and the .workers.dev address in the proxy field.

4. Test the fetch

A successful fetch displays a message that the page loaded. Run the analysis and check whether the extracted text includes the actual article content, not only the Salesforce page title or navigation.

If the Worker returns an error:

  • Hostname is not in the allowlist: check that ALLOWED_HOSTS contains the exact hostname in the address bar. Review redirects; the Worker blocks redirects to hosts that are not allowlisted.
  • Origin is not allowed: confirm SITE_ORIGIN is exactly https://tanmayi1996.github.io, without a trailing slash.
  • HTTP 401/403 or a login/challenge page: the article is not publicly readable to the Worker. Use the browser's Save page as HTML option or paste the visible article content.
  • Content is too short or incomplete: Salesforce may render the article using JavaScript. The Worker fetches HTML; it does not run the browser's JavaScript. Save the fully rendered page from your browser or paste the article text instead.

5. Security and limitations

  • The Worker accepts HTTPS URLs only and checks every redirect against the exact hostname allowlist.
  • It does not forward your browser cookies, Salesforce login, SSO session, or authorization headers.
  • It accepts HTML or plain text up to 2 MB and uses a 15-second fetch timeout.
  • The strict CORS origin check is not user authentication. The hostname allowlist is the main outbound restriction. Keep it narrow and configure rate limiting in Cloudflare.
  • Do not use the proxy for private, confidential, or customer data. Cloudflare may process request metadata as part of its service operation.
  • If the page is not publicly accessible or its content is generated only after client-side scripts run, use paste or file upload.
