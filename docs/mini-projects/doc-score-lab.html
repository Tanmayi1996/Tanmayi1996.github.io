Overview

DocScore Lab is a browser-based documentation review tool. It checks the structure and content of Markdown, plain-text, and HTML documentation and highlights patterns that may affect readability, task completion, technical completeness, and machine parsing.

Use the score to identify areas for editorial review. It is not a certification of documentation quality and does not replace subject-matter review, usability testing, or technical validation.

What the tool does: analyzes content structure and text using deterministic rules. It does not use a language model to invent feedback, and it does not send pasted or uploaded documentation to a server.

Run an audit

  1. Open DocScore Lab.
  2. Select Paste or Upload files.
  3. For pasted content, enter a document name and paste the complete Markdown, plain-text, or HTML page. For files, select one or more supported files.
  4. Select Analyze documentation.
  5. Review the overall score, category scores, priority suggestions, and document-level results.
  6. Expand Show check-by-check results to see which rules passed and which need attention.
  7. Select Copy report to copy a text summary of the audit.

Supported file types

FormatHow the tool reads it
Markdown (.md, .mdx)Checks heading, list, link, image, table, and fenced-code patterns.
Plain text (.txt)Checks text length, sentence patterns, and words. It cannot infer rich document structure unless it is represented in the text.
HTML (.html, .htm)Reads the document title, headings, links, image alt attributes, lists, tables, and code elements from the parsed page.

The maximum file size is 3 MB per file. You can select multiple files to compare a set of documents. You can also fetch one public page by URL when its server allows browser CORS access.

Audit one public documentation page by URL

  1. Open DocScore Lab and select Fetch URL.
  2. Enter the public HTTP or HTTPS URL for the documentation page.
  3. For a CORS-enabled site, select Fetch page and continue to step 6.
  4. For a site that blocks CORS, deploy the optional fetch proxy and paste its HTTPS Worker URL into Optional fetch proxy URL.
  5. Select Fetch page. When the page loads, select Analyze documentation.

The target site must allow cross-origin browser requests (CORS). Some documentation platforms block this by default. For those sites, deploy the optional restricted Cloudflare fetch proxy, enter its HTTPS URL in the proxy field, and fetch again. The proxy can read only public pages from hostnames you explicitly allowlist; it cannot sign in or bypass access controls. If the site requires login or returns a JavaScript shell, save the page as HTML or copy its visible content and use the upload or paste option. URL mode fetches one page only; it does not crawl a documentation site or follow links.

Audit the portfolio samples

  1. Open DocScore Lab.
  2. Select Audit my portfolio docs.
  3. Wait for the published sample pages to load and review the combined results.

The portfolio audit checks the nine published documentation samples for the four browser mini projects, implementation notes, validation plan, and three code-based projects. The report calculates an average across the documents and shows their individual scores.

Understand the score

DocScore Lab reports an overall score from 0 to 100. It evaluates six categories.

CategoryWeightWhat it checks
Structure and navigation20%Page title, one main heading, section headings, heading hierarchy, and scannable content.
Task readiness20%Purpose and audience, actionable procedures, prerequisites, expected results, and recovery guidance.
Technical completeness20%Examples, field definitions, version context, errors and constraints, and output descriptions.
Clarity and readability15%Average sentence length, paragraph length, passive-voice patterns, and content depth.
Links and references15%Reference links, descriptive link text, image alternative text, and reference context.
Machine readability10%Readable text volume, structured sections, semantic lists or tables, and labeled code blocks.

Each category is scored from 0 to 100. The overall score is the weighted average of the six category scores. Each individual rule is a pass or review result; the tool does not award partial points for a rule.

Read the suggestions

The suggestions list groups failed checks across the uploaded documents. A suggestion that appears in several documents is shown higher in the list because it affects more of the set.

  • Structure findings: add a specific page title, use one H1, add useful H2 sections, and avoid skipped heading levels.
  • Task-readiness findings: state the purpose, list prerequisites, write ordered steps, describe the expected result, and explain common recovery paths.
  • Technical findings: add realistic examples, define parameters and data types, state supported versions, and document errors or constraints.
  • Clarity findings: split long sentences and paragraphs, and use active voice when it makes the actor clearer.
  • Reference findings: add useful related links, write descriptive link labels, and provide alt text for informative images.
  • Machine-readability findings: organize content with headings, lists, tables, and language-labeled code blocks.

Review each suggestion in context. For example, passive voice is not always incorrect, and a long sentence can be appropriate when it expresses one precise condition. Do not change technically accurate content only to improve a score.

Privacy and limitations

  • Pasted text and uploaded files are processed in the browser. The tool does not transmit them to a portfolio backend.
  • Direct URL imports are requested by your browser. When you configure the optional Cloudflare proxy, the requested public URL and its response pass through that Worker. The Worker does not forward Salesforce cookies or credentials and is configured for an explicit hostname allowlist.
  • Do not use the proxy for confidential or internal-only documentation. Cloudflare may process request metadata as part of providing the Worker service.
  • The portfolio audit fetches the published sample pages from the same website.
  • The tool does not currently crawl arbitrary sites or test external link availability.
  • It does not verify whether statements, commands, API responses, or code samples are factually correct.
  • It does not evaluate real user task success, search analytics, security, accessibility conformance, page performance, agent retrieval, or API/MCP infrastructure.
  • Sentence splitting, word counting, and passive-voice detection use simple heuristics. Abbreviations, code, tables, and unusual punctuation can affect results.
  • A rule marked as passed means the pattern was found; it does not guarantee that the content is good.

Scoring method

Each category contains checks with fixed point values. The category score is calculated as the points earned divided by the total available points in that category, multiplied by 100. The category score is then multiplied by its weight to contribute to the overall score.

For a multi-document audit, DocScore Lab calculates each document score separately and reports the arithmetic average across the selected documents. Repeated failed checks are grouped to help prioritize common issues.

The method is intentionally visible so reviewers can understand why a document received a particular score. It is a standalone, content-level scoring rubric created for this portfolio tool.
