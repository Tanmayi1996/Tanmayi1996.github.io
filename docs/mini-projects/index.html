Browser-based mini projects

The portfolio website includes four small tools that demonstrate how a technical writer can make documentation tasks easier to understand and repeat.

Open the mini-project playground to try them.

ToolInputResultBest used for
Release note composerProduct, version, change type, title, descriptionMarkdown release-note draftFormatting a confirmed product change
API response explorerSample endpoint and optional demo token textExample HTTP request and responseExplaining API request and response structure
Documentation health analyzerParagraph or article excerptCounts and review suggestionsQuick editorial checks
Markdown table builderPipe-separated rowsMarkdown table syntaxPreparing tables for Markdown documentation

Choose a tool

  • Use the release note composer when you have a confirmed change to communicate.
  • Use the API response explorer to explain an HTTP exchange.
  • Use the documentation health analyzer to find patterns worth reviewing.
  • Use the Markdown table builder to convert notes into Markdown table syntax.

How the mini projects work

All four tools execute in the visitor's browser. They do not send entered text to a server. The API response explorer uses predefined examples; it does not send HTTP requests. The tools are demonstrations, not replacements for a production release-management system, API client, editorial review, or Markdown parser.
