Documentation Quality Checker

A Python command-line utility that scans Markdown files for common mechanical issues before peer review.

Overview

The Documentation Quality Checker scans Markdown files for common mechanical issues. It helps contributors catch a few problems before peer review. It is a starter linter, not a replacement for editorial judgment or a full Markdown parser.

Run the checker

You need Python 3.10 or later. The checker uses only the Python standard library.

  1. Clone the source repository.
  2. Open the documentation-quality-checker directory.
  3. Run:
python check_docs.py samples

Review the file names, line numbers, and messages in the output.

Checks performed

CheckWhat the tool looks for
HeadingAt least one Markdown heading in each file.
Placeholder textTODO, TBD, FIXME, and Lorem ipsum.
Relative linksLocal Markdown links whose target file does not exist.
Long prose linesNon-heading prose lines with more words than the configured threshold.

The default long-line threshold is 30 words.

Change the word threshold

Use --max-words to set a different limit.

python check_docs.py samples --max-words 25

Check one file

Pass a Markdown file path instead of a directory.

python check_docs.py samples/quickstart.md

Interpret the exit code

The checker exits with code 0 when it finds no issues and code 1 when it reports one or more issues. This lets a CI workflow use the result as a simple quality gate.

Run the tests

python -m unittest -v

The unit tests cover detection of placeholders and broken local links, along with a clean-file case.

Known limitations

The checker does not parse the full Markdown syntax tree. It does not check external URLs, validate code samples, evaluate accessibility, detect every style violation, or judge technical accuracy. A long sentence is not always unclear, and a short sentence is not always useful. Review each finding in context before you edit the source.
